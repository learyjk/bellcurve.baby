# Stripe Connect Express — Testing Guide

This document covers how to fully test the Stripe Connect Express integration
locally and in staging before going live.

## Prerequisites

1. **Stripe CLI** installed: https://stripe.com/docs/stripe-cli
2. **Real Stripe keys** in `.env.local` (test mode keys, starting with `sk_test_`)
3. All three Stripe env vars set:
   ```
   STRIPE_SECRET_KEY=sk_test_...
   NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_...
   STRIPE_WEBHOOK_SECRET=whsec_...   # generated by stripe listen (see below)
   # Note: SUPABASE_SERVICE_ROLE_KEY is NOT needed.
   # All webhook DB writes use SECURITY DEFINER Postgres functions via the anon key.
   ```
4. `NEXT_PUBLIC_BASE_URL` set so redirect URLs resolve correctly:
   ```
   NEXT_PUBLIC_BASE_URL=http://localhost:3000
   ```

---

## Step 0 — Run the DB migration

In Supabase SQL Editor, run `supabase/migrations/002_stripe_connect.sql`.

Verify:
```sql
SELECT column_name FROM information_schema.columns
WHERE table_name = 'pools'
  AND column_name IN ('stripe_account_id', 'stripe_onboarding_complete');
-- Should return 2 rows
```

## Step 1 — Enable Stripe Connect in your dashboard

1. Go to https://dashboard.stripe.com/settings/connect
2. Under "Integration", choose **Express**
3. Under "Branding", set your business name (shown to creators during onboarding)
4. Save. You do NOT need to activate Connect for testing — test mode works immediately.

---

## Step 2 — Start the webhook listener

In a new terminal:
```bash
stripe listen \
  --forward-to localhost:3000/api/stripe/webhook \
  --events checkout.session.completed,account.updated
```

Copy the `whsec_...` secret it prints and paste into `.env.local`:
```
STRIPE_WEBHOOK_SECRET=whsec_...
```

Restart the dev server so it picks up the new secret.

## Step 3 — Full happy path test

### 3a. Create a pool (as Pool Creator)

1. Sign up / log in as any user
2. Go to `/baby/create` and fill out the form
3. Submit → you should be redirected to `/baby/<slug>/connect`
4. You should see the "Connect Your Stripe Account" card

### 3b. Complete Stripe onboarding (test mode shortcuts)

1. Click **"Connect with Stripe"**
2. You're redirected to Stripe's hosted Express onboarding
3. Use these **test values** to skip real identity verification:
   - Phone: any valid format, then use `000-000` as verification code
   - SSN last 4: `0000`
   - Routing number: `110000000`
   - Account number: `000123456789`
   - Date of birth: any past date
4. Complete all steps and click Done
5. You should be redirected back to `/baby/<slug>?connect=success`
6. A green toast confirms: "🎉 Stripe connected!"
7. The yellow "Connect Stripe" banner is gone

### 3c. Verify in DB
```sql
SELECT slug, stripe_account_id, stripe_onboarding_complete
FROM pools WHERE slug = '<your-slug>';
-- stripe_account_id should be acct_xxx
-- stripe_onboarding_complete should be true
```

### 3d. Place a guess (as a different user / incognito)

1. Open incognito, sign up as a new user
2. Go to `/baby/<slug>`
3. Move the sliders and click "Place Guess for $X.XX"
4. Stripe Checkout opens — use test card `4242 4242 4242 4242`, any future date, any CVV
5. Payment succeeds → redirected to `/baby/<slug>?payment=success`
6. Toast: "Payment successful! Your guess has been recorded."
7. Check the guesses table:
```sql
SELECT * FROM guesses WHERE pool_id = '<pool-id>' ORDER BY created_at DESC LIMIT 1;
-- payment_status should be 'paid'
```

### 3e. Verify funds went to connected account

1. Go to https://dashboard.stripe.com/test/connect/accounts
2. Find the test account you created
3. Click into it → Payments → you should see the charge
4. The balance should reflect the transfer

## Step 4 — Edge case tests

### 4a. Guess on unconnected pool

1. Create a pool but do NOT complete Stripe onboarding
2. As another user, visit the pool and try to place a guess
3. Expected: error toast — "This pool isn't accepting payments yet"
4. The guess form submit does NOT redirect to Stripe

### 4b. Incomplete onboarding (user bails early)

1. Click "Connect with Stripe"
2. On Stripe's onboarding page, close the tab or click back
3. Stripe will redirect to the `refresh_url` → `/baby/<slug>/connect?status=refresh`
4. Expected: yellow warning card, "Resume Stripe Onboarding" button
5. Click Resume → onboarding continues with progress saved

### 4c. `account.updated` webhook sync

If onboarding completes in a separate browser session (or the return URL fails),
the webhook will sync status automatically:
```bash
# Simulate Stripe sending account.updated with charges_enabled: true
stripe trigger account.updated \
  --add account:id=acct_<your-test-account-id> \
  --add account:charges_enabled=true
```
Verify `stripe_onboarding_complete` flips to `true` in the DB.

### 4d. Duplicate payment prevention

Stripe CLI can resend events:
```bash
stripe events resend evt_<event-id>
```
The webhook's `payment_id` duplicate check prevents a second guess being inserted.

### 4e. Close pool flow

1. After some guesses are in, go to `/baby/<slug>/close`
2. Enter the actual birth date and weight
3. Rankings are computed and pool is locked
4. Visit `/baby/<slug>` → should show the locked winner display
5. Money is already in the creator's Stripe account from step 3e — no extra steps needed

## Step 5 — Stripe CLI triggers reference

```bash
# List recent events
stripe events list --limit 10

# Resend a specific event
stripe events resend evt_xxx

# Watch logs in real time
stripe logs tail

# Manually trigger checkout completed (fill in your pool/user IDs)
stripe trigger checkout.session.completed
```

## Going to production checklist

- [ ] Swap `sk_test_` → `sk_live_` keys in production env
- [ ] Swap `pk_test_` → `pk_live_` publishable key
- [ ] Register a new webhook endpoint in Stripe Dashboard → Webhooks:
      `https://yourdomain.com/api/stripe/webhook`
      Events: `checkout.session.completed`, `account.updated`
- [ ] Copy the new `whsec_` from the live webhook endpoint into prod env
- [ ] Set `NEXT_PUBLIC_BASE_URL=https://yourdomain.com` in prod
- [ ] Verify Connect settings at https://dashboard.stripe.com/settings/connect
- [ ] Test one real payment with a real card before announcing
